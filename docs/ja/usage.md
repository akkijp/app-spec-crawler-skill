# 使い方の詳細

[← README に戻る](../../README.ja.md)（日本語の README は `README.ja.md`。英語の README は [`README.md`](../../README.md)）· [English](../usage.md)

## コマンド

| コマンド | すること |
|---|---|
| `app-spec-crawler` / `help` | 使い方を出す |
| `app-spec-crawler doctor [--url URL]` | 今使えるかを表で出す。`--url` を付けると、そのアプリのタブが開いているかも見る |
| `app-spec-crawler crawl --url URL --out DIR` | 巡回する（`DIR/pages.json` と `DIR/screenshots/`） |
| `app-spec-crawler describe DIR [--lang CODE]` | 画面ごとの説明を書くための雛形 `DIR/descriptions.json` を作る。`--lang` で文書の言語を決める（`en` `ja` `zh` `es` `ko`） |
| `app-spec-crawler build DIR` | 画面仕様書 `DIR/book/` を作る |
| `app-spec-crawler write DIR` | システム概要書 `DIR/book/guide.html` を書く（数分。`--budget` で費用の上限、既定 8 ドル） |
| `app-spec-crawler verify DIR` | 文書を開いて幅 1440px / 390px で撮り、はみ出し・壊れた画像・書き漏れを確かめる（`DIR/verify/`） |

ふつうは Claude に「〇〇を巡回して仕様書を作って」と頼めば、Claude がこの順に進めます。

## 文書の言語

- 文書（画面仕様書とシステム概要書）は、Claude と話している言語で書かれます。
- 使える言語は 5 つです: `en` 英語、`ja` 日本語、`zh` 中国語（簡体字）、`es` スペイン語、`ko` 韓国語。それ以外の言語のときは英語になり、Claude がそのことを伝えます。
- 言語は `describe --lang CODE` で決まり、`descriptions.json` の `_lang` に入ります。`build` と `write` はそれに従います（どちらも `--lang CODE` で、その回だけ変えられます）。
- この決まりより前に作ったプロジェクトには `_lang` がありません。日本語として扱います。
- `descriptions.json` の `confidence` は、どの言語でも英語の `Verified` / `Inferred` / `To confirm` のどれかです。文書の上では、その言語の言葉（日本語なら 確認済 / 推定 / 要確認）で表示されます。
- 対象アプリの画面にある文字（ボタン名など）は、画面のとおりに引用します。訳しません。

## crawl のオプション

| オプション | 意味 |
|---|---|
| `--resume` | 途中で止まった巡回の続き。ログインし直して URL が変わっても続きから回る |
| `--scope-prefix URL` | この文字列で始まる URL だけ回す（既定: 起点と同じオリジン） |
| `--route-param NAME` | 画面を `?NAME=...` で切り替えるアプリで、その値を画面の住所として扱う |
| `--variant-param NAME` | 別の画面として扱うクエリ（複数可） |
| `--keep-query` | クエリが違う URL を別の画面として扱う |
| `--no-id-collapse` | `/items/1` と `/items/2` を同じ画面にまとめない |
| `--exclude REGEX` | 開かない URL（複数可） |
| `--extra-deny WORD` | 危険な URL とみなす言葉を足す（複数可） |
| `--allow-route PATH` | 危険な言葉・トークン・操作のパラメータを含んでも開いてよい画面（複数可） |
| `--allow-token-urls` | トークンと操作のパラメータの決まりを丸ごと外す。**危険です。** 検証用の環境で、利用者がはっきり求めたときだけ使う |
| `--hide SELECTOR` | 撮る前に隠す重なり（サイト内ヘルプ・チャット窓などの CSS セレクタ。複数可） |
| `--max-pages N` | 上限の画面数（既定 300） |
| `--max-depth N` / `--batch N` | 深さの上限（既定 10）/ 1 回に回す画面数（既定 30） |
| `--wait 秒` | 画面を開いてから最低限待つ時間（既定 1） |
| `--settle-max 秒` | 画面の描画が終わるのを待つ上限（既定 8） |
| `--no-dedupe` | 中身が同じ画面をまとめない |
| `--no-tabs` | ページ内タブもクリックしない |
| `--session-text REGEX` | ログイン切れを表す文言を足す（複数可） |
| `--retry-errors` | 前回エラーで取れなかった画面を取り直す（`--resume` と一緒に使う） |
| `--relogin コマンド` / `--relogin-max N` / `--relogin-timeout 秒` | ログインが切れたときに流すコマンド（終了コード 0 でログインし直せたとみなす）/ 上限の回数（既定 3）/ コマンドを待つ時間（既定 180） |

### 画面を撮るタイミング

画面は、描画が終わってから撮ります。ページの変化が止まるまで待ちます（最低 `--wait` 秒、最長 `--settle-max` 秒）。スクリーンショットに読み込み中の表示や空の枠が写るときは、`--settle-max` を大きくしてください。

### 同じ中身の画面

すでに撮った画面と中身が同じ画面は、重複として記録し、文書には足しません。`--no-dedupe` でこの動きを止められます。

### 開かない URL

ふつうのリンク（GET）を開くだけでデータが変わるアプリがあります（WordPress の「ゴミ箱へ移動」「有効化」はリンクです）。そのため、既定では次の URL を開きません。

- 危険な言葉（`logout` `delete` `approve` `export` など）を含む URL
- 状態を変えるためのトークンが付いた URL（`_wpnonce` `csrf_token` `authenticity_token` `sesskey` などのクエリ）
- 操作のパラメータ（`action=` `do=` `op=` `cmd=` `task=`）の値が、読み取りだけと分かっているもの（`edit` `view` `show` `list` `search` など）でない URL

開かなかった URL は、理由と一緒に `DIR/safety_report.json` に載ります。特定の画面を開いてよいときは `--allow-route PATH` で戻します。

## エラーのとき

失敗すると「✖ エラー / 原因 / 直し方」の 3 段で出ます。直し方にパッケージのインストールなどが含まれるとき、Claude は承認をもらってから実行します。

| 終了コード | 意味 |
|---|---|
| 0 | 成功 |
| 1 | その他 |
| 2 | 使い方の誤り |
| 3 | ログイン切れ（ログインし直して `--resume`） |
| 4 | Chrome につながらない |
| 5 | 必要なものが入っていない |
| 6 | 見た目の確認で問題あり |
| 7 | 画面仕様書の生成に失敗 |
| 8 | システム概要書の書き出しに失敗 |

## 注意

- **できるのは「見える範囲」の仕様です。** スクリーンショットと画面の構造から読み取った推定を含みます。「推定」「要確認」の項目は、原本の設計書や開発者に確かめてください。
- **スクリーンショットには実データが写ります。** 顧客名・従業員名などが写るので、できた文書の共有先・保存先に気を付けてください。
- **画面を開いただけで何かが変わるアプリがあります。** たとえば WordPress は「投稿を追加」の画面を開くたびに自動下書きを作ります。巡回の側からは分かりません。そういう画面を知っていたら Claude に伝えてください（`--exclude` で外します）。
- **`write` は Claude の利用料がかかります**（`claude -p` を 1 回呼ぶ。`--budget` で上限を決められる）。
- ログインの有効期限が短いアプリでは途中で切れることがあります。ログインし直して `--resume` で続きから回せます。
